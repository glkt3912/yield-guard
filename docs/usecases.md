# ユースケース一覧

Yield-Guard が解決するユーザーシナリオをまとめます。
各シナリオは「どんな人が・何を知りたくて・どの機能を使うか」の観点で記述します。

---

## UC-01: 土地価格の相場確認

**誰が**: 購入検討中の投資家  
**何を知りたいか**: 候補物件の土地値が地域相場と比べて割安か割高か  
**使う機能**: `GET /api/land-prices/stats`、`GET /api/land-prices/compare`

### シナリオ

```
1. 都道府県・市区町村・期間を指定して相場データを取得
2. 取引件数・平均坪単価・中央値・最小/最大を確認
3. 候補物件の土地価格・面積を入力して相場比較を実行
4. 「割安 / 相場 / 割高」の判定と中央値との乖離額を確認
```

**判定ロジック**: 入力坪単価が中央値±10%以内なら「相場」、下回れば「割安」、超えれば「割高」  
**注意点**: 取引件数が10件未満の場合は「データ不足警告」が表示される（参考値扱い）

## UC-02: 長期収支シミュレーション

**誰が**: 物件購入を検討中の投資家  
**何を知りたいか**: 購入後35年間のキャッシュフロー推移と税引後手残り  
**使う機能**: `POST /api/investment/analyze`

### シナリオ

```
1. 土地価格・建築費・月額賃料・ローン条件・空室率などを入力
2. 年次キャッシュフロー（税引前/税引後）・累積CFを確認
3. 投資回収年（breakEvenYear）を確認
4. 表面利回り・実質利回りが8%ラインを超えているか確認
5. 8%未満の場合: 達成に必要なコスト削減額または必要月額賃料を確認
```

**8%の意味**: 業界経験則による「最低限の投資妥当性ライン」（全宅連・不動産情報各社の慣習的指標）

## UC-03: デッドクロスリスクの把握

**誰が**: 融資を活用して物件購入を検討中の投資家  
**何を知りたいか**: 元金返済が減価償却費を超える時期（デッドクロス）がいつ来るか  
**使う機能**: `POST /api/investment/analyze`（DeadCrossChart で可視化）

### シナリオ

```
1. ローン条件・建物構造・築年数を入力してシミュレーション実行
2. DeadCrossChart で元金返済ラインと減価償却費ラインの交差を確認
3. デッドクロス開始年・継続期間を把握
4. 「帳簿上黒字なのに税負担が増える」時期を事前に認識して対策を検討
```

**注意**: デッドクロス中は課税所得が増えるため、税引後CFが圧迫される（黒字倒産リスク）

## UC-04: ストレステスト（最悪ケース試算）

**誰が**: リスク感度を確認したい投資家  
**何を知りたいか**: 金利上昇・空室悪化が重なった場合でも収支が成り立つか  
**使う機能**: `POST /api/investment/analyze`（スライダーで delta を調整）

### シナリオ

```
1. 通常条件でシミュレーション実行
2. 空室率上昇スライダー（+0〜30%）で空室悪化シナリオを設定
3. 金利上昇スライダー（+0〜3%）で金利上昇シナリオを設定
4. 年次CFがマイナスに転じる年を確認
5. 許容できるリスク水準かを判断
```

## UC-05: 出口戦略（売却シミュレーション）

**誰が**: 数年後の売却を見据えて購入を検討中の投資家  
**何を知りたいか**: 売却時の手残り（譲渡税・残債控除後）と最終的な資産増加額  
**使う機能**: `POST /api/investment/analyze`（ExitStrategy セクション）

### シナリオ

```
1. 売却目標年数・目標利回り（売却時NOI基準）を入力
2. 収益還元法による売却価格の試算を確認
3. 譲渡所得税（短期39.63% / 長期20.315% / 10年超14.21%）を確認
4. 売却手取り + 累積CF = 最終手残りを確認
5. 自己資金対比でのリターンを評価
```

## UC-06: エリア・市区町村を絞った相場調査

**誰が**: 特定エリアの投資を検討中の投資家  
**何を知りたいか**: 都道府県内の特定市区町村に絞った土地価格相場  
**使う機能**: `GET /api/municipalities`（市区町村ドロップダウン）

### シナリオ

```
1. 都道府県を選択すると市区町村一覧が動的に取得される
2. テキスト入力で市区町村をインクリメンタルサーチ → 1件一致で自動選択
3. 特定の市区町村を選択して相場を絞り込む
4. 市区町村未選択（全市区町村）での都道府県全体相場との比較が可能
5. 相場データ取得後、取引データから抽出した代表的な用途地域・建ぺい率・容積率を確認
```

## UC-07: 現況空室率と想定空室率の2軸比較

**誰が**: 稼働中の物件を購入検討中の投資家  
**何を知りたいか**: 「今の空室状況」と「長期的な想定空室率」を分けてリスクを把握したい  
**使う機能**: `POST /api/investment/analyze`（YieldAnalysis の3シナリオ比較テーブル）

### シナリオ

```
1. 現況空室率（現在の実態）と想定空室率（長期前提）を別々に入力
2. 3シナリオ比較テーブルで確認:
   ├─ 満室想定: 広告掲載の表面利回り基準
   ├─ 現況: 今すぐ購入した場合の実態利回り
   └─ ストレス: 現況空室 + スライダー上昇分の最悪ケース
3. 長期収支シミュレーション（YearlyResults）は「想定空室率」で計算
```

**ポイント**: 「現況の一時的な空室」と「長期の安定運用前提」を混同しないための機能

## UC-10: 土地値割れ判定

**誰が**: 中古物件・再建築不可リスクを気にする投資家  
**何を知りたいか**: 総取得価格が土地の相場価値を下回っているか（最悪でも土地売却で回収可能か）  
**使う機能**: `LandPriceAnalysis`（相場検索後に自動表示）

### シナリオ

```
1. 相場データ取得後、土地面積・土地価格・建築費を入力してシミュレーション実行
2. 土地値割れ判定セクションで3段階の判定を確認:
   ├─ 土地値割れ: 総取得価格 < 土地概算価値（解体・土地売却で回収可能。安全余白あり）
   ├─ 土地値近辺: 総取得価格 ≦ 土地概算価値 × 1.5（建物価値含む相場水準）
   └─ 土地値超:   総取得価格 > 土地概算価値 × 1.5（建物価値が消失すると含み損リスク）
3. 差額（概算価値 − 総取得価格）で安全余白の金額を確認
```

**計算式**: 土地概算価値 = 中央値坪単価（国交省API）× 土地面積（m²） ÷ 3.30578  
**注意**: 相場データは宅地取引の中央値。用途地域・接道状況により実際の価値は異なる

## UC-09: Critical Error判定（マイナス物件の一発退場）

**誰が**: 投資判断の基準となるリスクを事前に把握したい投資家  
**何を知りたいか**: 購入してはいけない物件を即座に識別したい  
**使う機能**: `POST /api/investment/analyze`（Dashboard の赤バナー表示）

### シナリオ

```
1. シミュレーション実行後、結果の最上部に赤/黄バナーが表示される
2. REJECT（⛔ 一発退場）: 致命的リスクを検出
   ├─ LAND_VALUE_GUARD: 積算評価額が購入総額の50%未満
   │   → 銀行担保評価が低く出口詰まりのリスク
   └─ DEADCROSS_EARLY: 10年以内にデッドクロス発生
       → 帳簿黒字でもキャッシュ不足（黒字倒産リスク）
3. WARNING（⚠ 警告）: 注意すべきリスクを検出（将来実装予定）
4. エラーなしの場合はバナー非表示
```

**積算評価の計算式**:
```
積算評価 = 土地価格 + 建築費 × (残存耐用年数 / 法定耐用年数)
閾値: 積算評価 < 購入総額 × 50% → REJECT
```

## UC-11: 諸経費明細・コスト内訳の可視化

**誰が**: 物件購入前に総コスト感を把握したい投資家  
**何を知りたいか**: 購入時に発生する各種費用（仲介手数料・印紙税・登録免許税・不動産取得税など）の内訳と、1年目の年間費用の構成比  
**使う機能**: `POST /api/investment/analyze`（CostBreakdown コンポーネント）

### シナリオ

```
1. シミュレーション実行後、コスト内訳セクションに自動表示
2. 初期投資内訳ドーナツグラフで確認:
   ├─ 土地・建物費用
   ├─ 仲介手数料（税込）
   ├─ 印紙税
   ├─ 登録免許税
   ├─ 不動産取得税（概算）
   └─ 固定資産税日割り精算（引渡月がある場合）
3. 取得時諸経費明細テーブルで各費用の金額を確認
4. 1年目の年間費用内訳（ローン返済・運営経費・所得税）の構成比を確認
```

**各費用の算出根拠**:
- 仲介手数料: 宅建業法46条（物件価格帯別の上限×1.1）
- 印紙税: 国税庁告示の売買契約書金額区分
- 登録免許税: 土地・建物の所有権移転 + 抵当権設定（軽減措置2026/3/31まで）
- 不動産取得税: 固定資産税評価額×3%（住宅用地軽減・新築控除適用）
- 固定資産税日割り: 引渡日以降の年税額按分（うるう年対応）

## UC-08: 用途地域リスク警告

**誰が**: 投資候補エリアの法的リスクを事前に把握したい投資家  
**何を知りたいか**: 取引データが示すエリアの用途地域が投資に不適切なリスクを持っていないか  
**使う機能**: `GET /api/land-prices/compare`（LandPriceAnalysis のリスクパネル）

### シナリオ

```
1. 相場データ取得後、都市計画リスクパネルが自動表示
2. リスクレベル別に警告を確認:
   ├─ ERROR（赤）: 市街化調整区域
   │   → 建築・用途変更が原則制限、建替え困難リスク
   ├─ WARNING（黄）: 非線引き区域・都市計画区域外
   │   → インフラ整備遅延・資産価値不安定リスク
   └─ WARNING（黄）: 市街化調整区域が30%以上混在
       → 対象物件の区域区分を個別確認すべき
3. リスクなしの場合はパネル非表示
```

**検出ロジック**: 取引データの `CityPlanning` フィールドの最頻値と混在率から判定。個々の物件の正確な区域区分は法務局・市区町村窓口で確認すること。

## UC-12: 用途地域リスク警告（手動入力）

**誰が**: 物件の用途地域を把握している投資家  
**何を知りたいか**: 入力した用途地域が賃貸投資に適しているかをシミュレーション前に確認したい  
**使う機能**: `InvestmentForm` の用途地域ドロップダウン（フロントエンドのみ・APIなし）

### シナリオ

```
1. 投資条件フォームの「用途地域（任意）」から用途地域を選択
2. 選択直後にリスクバナーがインラインで表示される:
   ├─ 高リスク（赤）: 工業地域・工業専用地域・市街化調整区域
   ├─ 中リスク（黄）: 準工業地域
   ├─ 低リスク（青）: 近隣商業地域・商業地域
   └─ 良好（緑）: 住居系・田園住居地域
3. リスクの詳細メッセージを確認してシミュレーション実行を判断
```

**UC-08との違い**: UC-08 は相場データ取得後に取引データから自動検出するもの。UC-12 はユーザーが用途地域を知っている場合に手動入力して即時確認するもの。

## UC-13: 築年数・駅距離・需要スコア補正による理論価格と乖離率の確認

**誰が**: 物件の築年数・最寄り駅距離・駅規模を把握している投資家  
**何を知りたいか**: 近隣取引事例の中央値坪単価を基準に、物件固有の条件（築年数・駅距離・駅の乗降客数規模）を補正した「理論価格」と、販売価格との乖離率を確認したい  
**使う機能**: `GET /api/station-ridership`、`GET /api/land-prices/estimate`（LandPriceAnalysis の乗降客数・理論価格パネル）

### シナリオ

```
1. 投資条件フォームで「築年数」「最寄り駅徒歩（任意）」を入力
2. 「相場データを取得」を押すと station-ridership・estimate エンドポイントも自動呼び出し
3. LandPriceAnalysis に乗降客数パネル（紫）が表示される:
   ├─ 駅名（路線名）
   ├─ 乗降客数/日（カンマ区切り）
   └─ 需要スコア A〜E（カラーラベル）
4. LandPriceAnalysis に理論価格パネルが表示される:
   ├─ 理論価格（円）
   ├─ 乖離率 %（+が割高、-が割安）
   │   > ±20% で赤/緑の強調表示
   ├─ 築年数補正 %（取引事例中央値との差から算出）
   ├─ 駅距離補正 %（station_minutes 入力時のみ表示）
   └─ 需要スコア補正 %（ridership_score 指定時のみ表示）
5. 取引事例の築年数データが少ない場合は「参考値」注記を表示
```

**補正係数の意味**:
- 築年数補正: 物件が中央値より新しいほど +（価格上乗せ）、古いほど −（±30%クランプ）
- 駅距離補正: 物件が中央値より駅近ほど +、駅遠ほど −（±20%クランプ）
- 需要スコア補正: A=+15%, B=+8%, C=0%, D=-8%, E=-15%（駅規模による賃貸需要の強弱を反映）

**需要スコアのユースケース例**:
- 渋谷駅（36万人/日）→ スコアA → 補正 +15%（大型駅プレミアム）
- 地方小駅（2,000人/日）→ スコアD → 補正 -8%（需要希薄による割引）

## UC-14: 都市計画リスク自動検出（MLIT 専用 API 経由）

**誰が**: 投資候補物件の都市計画上のリスクを API データで客観的に把握したい投資家  
**何を知りたいか**: 立地適正化計画・大規模盛土・都市計画道路・災害履歴の 4 リスクが物件周辺に存在するか  
**使う機能**: `GET /api/urban-risks`（LandPriceAnalysis の都市計画リスクパネル）

### シナリオ

```
1. 相場データ取得フォームに緯度・経度が含まれる物件情報を入力
2. 「相場データを取得」押下時に /api/urban-risks を /api/population-forecast と並行呼び出し
3. LandPriceAnalysis に都市計画リスク警告バナー（黄）が表示される:
   ├─ OUTSIDE_RESIDENTIAL_GUIDANCE: 居住誘導区域外の可能性（XKT003）
   ├─ LARGE_EMBANKMENT: 大規模盛土造成地（XKT020）
   ├─ URBAN_PLANNING_ROAD: 都市計画道路区域内（XKT030）
   └─ DISASTER_HISTORY: 災害履歴あり（XST001）
4. リスクなしの場合はパネル非表示
```

**UC-08 との違い**: UC-08 は取引テキスト（XIT001 の `CityPlanning` フィールド）からエリア全体の用途地域を推定するもの。UC-14 は MLIT 専用タイル API からピンポイントで物件座標の都市計画リスクを取得するもの。両者は `code` 重複排除してマージ表示される。
